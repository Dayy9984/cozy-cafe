# 04 아트 가이드·제작 목록 — v0.8
## v0.8 공간·시각 규격 — 최신 사용자 정정
- 윗면은 **32×16px**, 공간 기준은 **32×32px**다.
- **4px 두께는 옆면 그림에만 존재**한다. 충돌 높이·단차·논리 Z·통행·정산에 쓰지 않는다.
- 32×32에 두께를 더한 **32×34 규격은 사용하지 않는다**. 작업 캔버스는 공간 기준 32×32 안에서 관리한다.
- **탁자·의자 표시 기준점 = 바닥 배치 기준점 + (0, -8px)**. 원본 크기/줌 1배 기준이다.
- 4px를 추가로 빼서 -12px로 만들거나, PNG와 엔진에서 각각 -8px를 적용해 -16px로 만들지 않는다.
- 논리 셀·점유·문/의자 연결·충돌·동선·깊이 정렬 키·판매량은 이 시각 보정으로 바뀌지 않는다.
- 캐릭터·카운터·머신·UI 전체에 -8px를 전역 적용하지 않는다. 앉은 인물/머신은 부모의 명시 부착점만 따른다.

### 좌표 구현 기본값과 사용자 확정을 구분
32×16/32×32/시각4/탁자·의자-8은 사용자 확정이다. 32×32를 셀 이동 피치나 실제 부피로 해석하지 않는다.
이 패키지의 **구현 기본값**은 윗면 32×16을 연속 투영 영역으로 해석해 반폭32/반높이16를 사용한다.
이는 사용자가 픽셀 경계·격자 피치까지 지정했다는 뜻이 아니다. 31px 래스터와 연속 투영의 경계를
검증할 원본 좌표는 제공되지 않았으므로, 격자 샘플을 실물 검수하고 이 기본값의 근거를 기록한다.
실수 좌표로 변환·역변환하고 최종 화면 합성에서만 동일 규칙으로 픽셀 스냅한다. 매 칸 16를 먼저
15나16으로 잘라 누적하지 않는다. 원작의 정확한 투영 구현이라고 주장하지 않는다.

### 실제 에셋 정렬
바닥 작업 캔버스32×32 안에서 윗면32×16과 시각 측면을 관리한다. 캔버스 바닥을 자동 앵커로 삼지 않는다.
윗면의 실제 bounds와 원점을 metadata에 기록하며 모든 바닥 스타일이 같은 배치 기준을 공유한다.
탁자/의자 원화는 보정 전 기준점으로 정렬하고 엔진 render_offset_px=[0,-8]로 한 번만 올린다.
이미 원화에 -8 보정이 포함되었다면 baked_alignment_offset_px를 기록하거나 정규화한다.
비주얼 표시 이동은 별도 Sprite/Render 자식에서만 수행하고 논리 root/collider/path node는 옮기지 않는다.
정렬 기준점, 선택 윤곽·고스트·마우스 선택도 같은 transform을 사용한다. 선택 후 셀은 보정 전 배치 정보로 확인한다.
4방향 회전에서 위로8px는 계속 화면 위이며 좌·우로 회전하지 않는다. 스툴은 MVP의 의자류 별칭으로 같은 규칙을 사용한다.
기존 캐릭터 셀·가구 PNG 크기는 개별 투명 여백 규격이며 바닥 공간32×32에 강제 맞추지 않는다.
앉은 캐릭터는 시각 seat attachment를 따라가되, 모든 서 있는 캐릭터에 -8을 일괄 적용하지 않는다.

## 인물 최소 리소스 — 대량 완성형 시트 금지
공통 rig/몸체 **1개**, 그 몸체를 조합한 시작 프리셋 **3개**(새 몸체 3개가 아님).
헤어4, 의상3, 직원 앞치마1, 안경2(+없음). 피부6·헤어8·의상8색은 팔레트 데이터.
몸체32×32 셀·앵커(16,8)는 MVP 제안값. 기준 타일 옆에서 확인 후 조정해도 전 파츠를 함께 조정.
방향4. body/outfit/앞치마는 idle1·walk4·sit1·work2 = 방향당8프레임으로 첫 rig를 검증.
머리/안경은 방향별 부착점에 붙여 기본 동작 재사용. 필요 동작만 예외 프레임 제작.
머리뒤→몸체/의상→앞치마→머리앞→안경 순서도 방향별 규칙으로 둔다. 모자/긴머리 충돌은 호환 태그.
파츠 하나는 모든 같은 body 프리셋과 같은 프레임번호/캔버스/앵커/애니메이션 시간을 공유.
걷기 foot sliding·관절/의상 이탈은 반드시 실제 loop로 검사. static image 확인만으로 통과하지 않음.
피부/옷/헤어 색상 마스크를 분리하고 고정 그림자/눈동자까지 통째로 tint하지 않음.
body2·헤어8·안경4·복잡한 모자/가방 등 이전 제안은 MVP 필수가 아니다.

## UI/UX도 제작 파이프라인에 포함
AI는 스타일 보드·아이콘·패널 스킨 후보. 한 장 UI를 완성 화면으로 쓰지 않음.
평면 UI를 아이소 다이아몬드로 강제하지 않음. normal/hover/pressed/disabled/focus 상태,
9-slice 여백·anchor·패딩·클릭영역·키보드 focus를 데이터로 관리. 글자는 엔진에서 렌더.
한글/긴 메뉴명/작은 창/DPI125·150·200%/Ctrl·Cmd/IME 조합/키보드 탐색을 실물 검수.
스타일 이미지를 생성했다고 UX가 구현된 것은 아니다.

## 이미지 생성 → 게임자산
Codex ChatGPT OAuth → 명시 provider codex → Sunburst 요청 → raw PNG+보고서 → 후보검토 →
선택 idle anchor 고정 → 상태 row 생성 → 알파/컴포넌트/격자보정 → 셀/파츠/팔레트 → atlas+frame_layout.
단순 축소(raw resize)로 최종 도트를 만들었다고 하지 않음. 재생성은 실패 상태 row만.
`sprite-gen` 도구를 사용하고 지원 범위는 설치한 commit에서 재검증한다. UI 후보도 curation 대상.
팔레트/안경 변형마다 이미지 모델을 다시 호출하지 않음. 변형은 결정론 합성/팔레트 교체.
원작 시트는 스타일/구조 확인용. 직접 제작할 canonical base는 원작 그대로의 복제 요청이 아님.
